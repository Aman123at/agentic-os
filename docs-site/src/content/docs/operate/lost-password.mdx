:::danger[There's no email reset and no reset link]
Agentic OS has no email address for you and no "forgot password" link. Getting back in needs **root access to
the machine**: SSH on a native install, or Docker on a Compose install. **If you've lost both the password and
SSH access, the machine can't be recovered through Agentic OS.**
:::

## Lost the one-time password before signing in?

The installer shows it only once. Recover exactly as below: remove the account and create it again, which
prints a new one-time password.

## Reset the Desktop account

This release has no dedicated reset command yet. You reset the account by **deleting it** from the database
and **creating it again** with `aos mode ui`, which prints a fresh one-time password. Your Tasks, files,
settings and API key aren't touched.

<Tabs syncKey="install-type">
  <TabItem label="Native install">
    <Steps>

    1. **SSH to the server** and install the SQLite command-line tool:

       ```bash
       sudo apt install -y sqlite3
       ```

    2. **Stop the service and back up the database:**

       ```bash
       sudo aos daemon stop
       sudo cp /var/lib/aos/aos.db /var/lib/aos/aos.db.bak
       ```

    3. **Remove the account and its sign-ins:**

       ```bash
       sudo sqlite3 /var/lib/aos/aos.db "DELETE FROM refresh_tokens; DELETE FROM users;"
       ```

    4. **Start the service and create the account again.** This prints a new one-time password:

       ```bash
       sudo aos daemon start
       sudo aos mode ui
       ```

    5. **Sign in** at `http://<server-ip>:7700` as `admin` with the new password, then choose your own.

    </Steps>
  </TabItem>
  <TabItem label="Docker Compose">
    <Steps>

    1. **Install SQLite inside the container:**

       ```bash
       docker compose exec aos apt-get install -y sqlite3
       ```

    2. **Remove the account and its sign-ins:**

       ```bash
       docker compose exec aos sqlite3 /var/lib/aos/aos.db "DELETE FROM refresh_tokens; DELETE FROM users;"
       ```

    3. **Create the account again.** This prints a new one-time password; ignore a closing message about
       `systemctl`:

       ```bash
       docker compose exec aos aos mode ui
       ```

    4. **Sign in** at `http://localhost:7700` as `admin`, then choose your own password.

    </Steps>
  </TabItem>
</Tabs>

:::note
The account always lives in the **Standard** database, `/var/lib/aos/aos.db`, even while the machine is in
Root Mode, so these steps work in either Realm.
:::

## Protect yourself for next time

- **Store the password in a password manager.**
- **Keep SSH access working.** Keep a second SSH key somewhere safe, and know your provider's rescue console.
